# 性能优化验证 · 2.1.0

保留人物、小船、溪龙和茶杯的原始 GLB、PBR 贴图、划桨动画、季节配色与游戏规则。优化版默认自动画质；不是此前的小红书 2D 兼容版本。

## 实施内容

- 对实例化植物按相机视锥筛选，保留边缘余量和近处阴影投射物；镜头未变化时不重复上传实例矩阵。
- 远处花瓣、叶片、荷花、苔石、积雪和冰柱采用相同参数曲面的低细分版本，近景使用原始几何。
- 河岸区块按帧分批构建，优先当前位置，再提前准备前方区块；雪层逐行计算，避免同步完成整个冬季区块。取消构建时释放临时资源。
- 自动档限制渲染像素和阴影分辨率，持续慢帧时逐级降低渲染分辨率，并缓慢恢复；加载尖峰不触发降档。菜单、观景和实际游戏均适用。
- 暂停和结算时限制为约 5 帧/秒，减少空闲消耗。极致档仍保留最高画质设置，不自动调整分辨率。

## 相同视角的绘制量

本机 Codex 浏览器、WebGPU、960×540 CSS 视口、设备像素比 2。旧版默认极致；新版默认自动档初始像素比 1.5。数据包含水面捕获、阴影等通道的三角面提交，不能当作独立模型面数。观景位置分别为 0、480、780、1080 米；剔除加载期采样。

| 春 | 56,981,887 | 18,177,139 | 68% |

中间验证记录见 performance-summary.json。春季帧率中位数由 44 提升到 60，冬季由 61 提升到 67；夏秋在这轮固定分辨率采样中仍约 41–44 帧，未获得可靠的帧率提升。随后加入了静止镜头跳过矩阵上传，并让观景模式启用自动分辨率。此记录不代表所有设备或手机能稳定 60 帧，不能只根据三角面降幅推算帧率。

## 构建与操作验证

- 63 项 Node 测试通过，覆盖原有玩法规则、控制、帧率调节、近远景裁剪、嵌套实例与取消任务资源释放。
- 资源校验无缺失；四个 GLB 的 SHA-256 与原版一致，角色的 Paddle_Cycle 动画保留。
- 实机打开四季观景并保存截图；启动实际航行到 178 米，发生正常碰撞与结算。重开、暂停、恢复、反击、跃浪均作操作检查。这不是全程通关验证。
- Node 几何构建探针：冬季四区块同步准备约 1.45 秒；优化后总工作分步执行，单步最长约 33 毫秒（该探针不包含 GPU 上传/着色器编译）。春、夏、秋、冬最大步骤分别约 13、31、47、33 毫秒，仍有可优化的首次地标构建。
- 首次切季仍需要加载与编译；分批构建主要改善连续航行时一次性长停顿。

WebGL2 兼容路径也完成首次渲染和观景检查；竖版视口下人物、水面和植物可见。本机该路径仍约 24 帧，优先使用默认的 WebGPU 路径。修复了自动分辨率改变尺寸时误显示观景触控按钮的问题。

构建产物的游戏模块、启动脚本与 CSS 加入一致的内容版本号，避免浏览器缓存混用新旧模块而导致启动失败；新增 3 项缓存引用测试。原始源码仍可直接通过本地服务器运行。
